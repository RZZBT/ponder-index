# Ponder index tools

`../docs/` is the published folder (GitHub Pages serves it from the `/docs` folder). It is **generated**; edit the generator, not the JSON.

```
npm run build     generate, check the layout, check NumPy examples against real NumPy, run `ponder check-index`
npm run verify    `ponder check` every document against the real, downloaded package (+ exact Rust symbol check)
npm run truth     run the other libraries' examples in the real libraries (Rust: one cargo program, all 120 examples)
npm run all       all three, in that order (use this before publishing)
npm run symbols   re-derive src/rust-symbols.json from the crates' sources (after adding a Rust animation)
node rust/std-symbols.cjs   re-derive src/rust-std-symbols.json from the toolchain's rust-src (Rust standard library)
```

## Setup

- Node 18+ and Python 3 on PATH; Rust (cargo) for the Rust truth check.
- `PONDER_PYTHON`: a Python that has NumPy installed (default: `python`). The build compares every NumPy example with it.
- `PONDER_CLI`: the Ponder command line tool, `dist/ponder.cjs` of the Ponder project (see `config.cjs` for the default).
- `verify` and `truth` download packages into `.cache/` (git-ignored): lodash, date-fns 2 and 4, NumPy 2.x and the 1.26 wheel,
  more-itertools, samber/lo, illuminate/collections, Guava (latest and 20.0), commons-lang3, and for each of the 15 crates
  the newest version and the oldest version of its range.
  Nothing downloaded is executed: npm runs with `--ignore-scripts`, pip takes wheels only, archives are only unpacked.
  The exception is the Rust truth check, which compiles the crates with cargo (that is how their examples are run).
- Options: `node verify.cjs --only <part of the file path>`; `TRUTH_ONLY="rust crates"` and `RUST_ONLY=regex,chrono`
  for `truth/run.cjs`; `CARGO_BUILD_JOBS` (default 2, to keep memory use low).

## Layout

```
build.cjs            entry point: generate -> layout check -> write -> ponder check-index
verify.cjs           ponder check against installed packages (version-aware); exact IDE-symbol check for crates
truth/run.cjs        examples of lodash, date-fns, more-itertools and all Rust crates run in the real libraries
truth/rust/          Cargo.toml + prelude.rs of the Rust truth program (main.rs is generated into .cache/rust-truth)
config.cjs           the only place with machine paths / environment variables
src/lib.cjs, lib2.cjs      animation building blocks (actors, slides, step/grid templates)
src/packages.cjs     the small packages + the layout validator (stage bounds, overlaps, slide counts, aliases)
src/collide.cjs      validator rule: text must not overlap other text or boxes it does not belong to
src/numpy.cjs        NumPy symbols (per version generation) and the truth check; specs live in batch2.cjs, batch3.cjs
src/rust/            the Rust crates (plan "Rust 1.98 / Ponder 0.2.1": 120 animations in 15 crates)
  index.cjs            crate list, version ranges, file names; assembles v1/crates/*.json and the truth cases
  scene.cjs            Rust scene builder and templates: pick (rows -> outputs), cells (strings), lines, graph
  itertools.cjs, regex.cjs, serde_json.cjs, chrono.cjs, indexmap.cjs, strsim.cjs, num_integer.cjs, petgraph.cjs,
  text_crates.cjs      (heck, textwrap, semver, base64, hex, url, unicode-segmentation)
src/rust-symbols.json  symbol + aliases of every Rust animation (generated by rust/symbols.cjs, committed)
src/rust_std/        the Rust standard library for Ponder 0.3 (2425 animations, 61 modules: every stable non-SIMD function of Rust 1.98; ints.cjs covers macro-generated integer methods, q01-q03 the iterator overrides, r01-r09 the unsafe and low-level API)
  index.cjs            module files, assembly into v1/std/rust/<module>.json (module = where the IDE jumps to)
  kit.cjs              compact step notation for pick/cells/lines; the truth expectation is the scene's result
  iter, iter2, vec, slice, str, string, option, result, collections, misc, extras, more1-3, ints, p05-p18, q01-q23 .cjs   the animations
src/rust-std-symbols.json  symbol, aliases and module of every std animation (rust/std-symbols.cjs, committed)
rust/std.cjs, rust/std-symbols.cjs   find rust-src (rustup component add rust-src) and build the std symbols
truth/rust-std/      the std truth program (no dependencies, so no crate trait changes which method is called);
                     run alone with TRUTH_ONLY="rust std", or RUST_STD_ONLY=iter/,vec/ for some animations
rust/crates.cjs      downloads crate sources from crates.io
rust/locate.cjs      finds the declaration of a function and builds the symbols VS Code and RustRover produce for it
rust/symbols.cjs     writes src/rust-symbols.json from several versions of each crate
src/write.cjs        compact JSON, splits every version range into documents under the format limits, index.html
src/defs.py          finds the file that defines a NumPy function
analysis/            coverage helpers (which NumPy functions exist / are animated)
```

## Rules the generator keeps

- **Limits:** a file is at most 2 MiB; a document at most 256 KiB and 64 animations. `write.cjs` splits a version range
  into several documents with the same `versions` value (60 animations / 200 KiB each, original order), so IDEs, which
  merge every matching document, see the same animations.
- **Symbols:** the primary symbol is built from the file that declares the function. `sym:` paths are relative to the
  installed package's root folder (`_core/fromnumeric.py:clip`, not `numpy/_core/...`), with the `.pyi` stub as a second
  alias because editors often jump to it. Documents are version-pure: the NumPy 1.x document only has 1.x paths.
- **Rust symbols** are `rust:<crate>::<modules from the file path>::<container>::<fn>`, where the container is the trait
  or the type of the `impl` block that declares the method (rust-analyzer's outline names). Where a call lands in an
  `impl Trait for Type` block, the primary is the impl (`rust:heck::snake::str::to_snake_case`) and the trait
  declaration is an alias. Also aliased: RustRover's form (it drops the container when the impl block has doc comments
  or attributes above it), older file layouts (textwrap 0.16.0 `lib.rs`, chrono `naive/date.rs`), `sym:` paths.
  `verify` requires every install in a range to produce one of the symbols, and the newest to produce the primary.
  Macro-generated impls (num-integer's `impl_integer_for_isize!`) are not used: their outline name is the macro's, the
  same for every method, so the trait declaration is the primary instead.
- **File names:** clients request the normalized crate name: `serde_json` is `v1/crates/serde-json.json`.
- **No unreachable aliases:** public re-export paths (`py:numpy.clip`, `py:more_itertools.chunked`) are never produced by
  any IDE's candidate algorithm and fail `ponder check`, so they are not written.
- **Truth:** every example result an animation shows is run in the real library. Rust: each animation carries `rs`, the
  code that computes its result; the result must equal `expect` and the animation must show it. Java, Go and PHP
  examples (Guava, commons-lang3, samber/lo, illuminate/collections) are NOT run by these tools: no runtime is installed here.
